# 脚本拨测

周期性健康检查通过「拨测任务 → 脚本运行」调用已有自动化任务。先在自动化任务管理中配置脚本或仓库、执行节点及超时，再在拨测中选择任务、周期和故障中心。拨测页面不能覆盖脚本、节点或超时。

## 执行与结果

- 每次执行读取自动化任务当前配置。任务被停用或删除时，拨测失败；不会回退为本机执行。
- 自动化任务统一执行，执行结果同时写入自动化执行记录（触发方式为 `probe`）和拨测记录。试运行也记录自动化执行日志，但不会保存拨测记录或触发拨测告警。
- 退出码 `0` 表示成功；非零退出码、执行异常或超时表示失败。标准输出和标准错误合并展示，沿用自动化任务输出截断规则。
- 自动化任务绑定的节点用于拨测趋势、失败/恢复计数和告警；调用方不再保存独立的执行节点配置。
- 调度最低周期为 10 秒。同一拨测任务已有执行未结束时不重复启动。
- 被拨测任务或故障处置引用的自动化任务不能直接删除，必须先解除引用。
- 故障中心处置同样只引用自动化任务；旧的脚本、工作流和 Webhook 直执行方式不再执行，编辑时需重新选择自动化任务。

配置存储于拨测任务的 `config`：

```json
{
  "automation_task_id": 12,
  "alert_detail": "核心进程健康检查失败"
}
```

YAML 导入/导出使用相同配置。旧 `script_id`、`execution_nodes`、`timeout_ms` 配置不会自动转换或猜测对应任务，需在编辑页重新绑定自动化任务。旧记录保留。

## 独立定时任务下线

旧的定时任务页面、API、Cron 调度和新增权限入口已移除。旧菜单在服务端菜单返回时过滤，旧页面地址跳转到拨测任务。脚本库、工作流和自动化处置继续保留。

旧定时任务及执行记录保留在数据库中，不删除、不继续执行。服务启动时终止仍活跃的旧定时任务告警，历史告警和通知记录仍可查询。旧 Cron 表达式、工作流定时任务不自动转换为固定周期脚本拨测；需要继续的健康检查，应按新配置创建脚本拨测任务。

## 开发验证

执行 `go test ./...` 验证后端；前端使用 Vite 开发模式，无需生成 `web/dist`。新增测试覆盖 Shell/Python 真实执行、退出码、超时、输出截断、自动化任务引用保护、配置 CRUD/导入、告警触发与恢复、调度与旧接口下线。

独立的即时拨测页面与菜单已移除，旧地址跳转到新建拨测任务。任务编辑页继续使用 `/api/instant-probe` 测试接口，无需先保存任务。
